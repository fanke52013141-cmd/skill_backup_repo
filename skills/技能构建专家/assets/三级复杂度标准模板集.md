# 三级复杂度标准模板集

根据需求复杂度定级结果（轻量 / 中等 / 复杂），选用对应重量的模板生成技能，切勿对所有需求机械套用同一套重型模板。

## 目录

1. 轻量级 Skill 模板（默认首选 MVP：单文件、单一流程、低风险）
2. 中等复杂度 Skill 模板（多步骤、含分支决策表、三态示例与外置脚本/参考）
3. 复杂级 Skill 模板（主子 Skill 协同编排、前置/后续/互斥关系、全目录拆分）

## 执行流程

复制以下进度清单跟踪执行状态：

- [ ] Step 1: 前置环境与输入校验
- [ ] Step 2: 扫描并生成中间处理计划
- [ ] Step 3: 按分支规则执行核心处理
- [ ] Step 4: 运行验证门禁并输出总结报告

### Step 1: 前置环境与输入校验

- **目的**：确保依赖齐备且输入路径安全合法。
- **操作**：运行 `python3 scripts/check_env.py --input "$TARGET_PATH"`。
- **分支判断**：若发现未保存改动，先提示用户提交或暂存。
- **检查点**：脚本返回退出码 `0`。
- **失败处理**：环境缺失时打印具体安装指令并终止流程。

### Step 2: 扫描并生成中间处理计划（Plan-Validate-Execute）

- **目的**：在真正修改文件前锁定影响范围并校验映射合法性。
- **操作**：读取 [references/映射规范.md](references/映射规范.md)，生成 `plan.json` 并运行 `python3 scripts/validate_plan.py plan.json`。
- **检查点**：`plan.json` 通过全部字段与类型校验。
- **失败处理**：根据 `stderr` 报错修正计划文件并重跑校验，未通过前严禁进入 Step 3。

### Step 3: 按分支规则执行核心处理

- **目的**：按场景特征执行差异化转换。
- **操作**：根据以下分支决策表处理每个目标项（超时阈值建议设为 15 至 30 秒，依据单模块平均编译耗时确定）：

| 输入特征 | 处理动作 | 验证要求 |
| :--- | :--- | :--- |
| **场景 A（常规结构）** | 使用默认转换规则直接改写 | 静态语法检查通过 |
| **场景 B（含自定义扩展）** | 保留原扩展钩子并注入兼容适配层 | 额外运行集成测试 |
| **场景 C（含高危外部调用）** | 仅生成带 `[需人工确认]` 标记的补丁文件 | 禁止自动覆盖原文件 |

- **检查点**：所有处理项均已按对应分支完成改写且无语法错误。
- **失败处理**：单文件转换失败时立即回滚该文件改动并记录至未处理清单。

### Step 4: 运行验证门禁并输出总结报告

- **目的**：确认改动未引入回归缺陷并生成可审计摘要。
- **操作**：依次执行下方“验证清单”中的命令，并汇总已修改文件、跳过项与后续人工核对建议。
- **检查点**：所有测试与静态检查命令退出码均为 `0`。
- **失败处理**：若测试失败，根据报错定位修复；若连续修复 2 次仍失败，执行 `git checkout -- <文件>` 回滚并报告根因。

# [主技能名称]（全局编排器）

## 目标

作为顶层编排技能，协调多个独立子技能与校验脚本，按严格阶段门禁完成端到端系统改造。

## 适用判断与技能协同关系

- **前置依赖技能**：执行前需已完成 `[前置诊断或备份技能名称]`。
- **包含子技能列表**：
  1. `[子技能 A 名称]`：负责数据层 Schema 备份与迁移。
  2. `[子技能 B 名称]`：负责服务层接口改造与契约生成。
  3. `[子技能 C 名称]`：负责调用方适配与端到端回归验证。
- **互斥技能**：执行期间切勿同时激活 `[存在冲突的技能名称]`。

## 非目标

- 主技能本身不内嵌各子阶段的具体代码改写细则（由各子技能或 `references/` 承载）。
- 不允许跳过上一阶段的验证门禁直接启动下一阶段子技能。

## 目录结构约定

- `scripts/preflight_check.py`：全局前置环境与权限检查脚本。
- `scripts/verify_stage.py`：跨阶段交付物契约一致性校验脚本。
- `references/阶段移交契约.md`：定义各阶段之间传递的中间态 JSON Schema（单层直接引用）。
- `evaluation/端到端评测集.json`：存放触发准确率与全链路完成率评估用例。
