## O1 后台字段拆分

**输入**：根据文字原型写管理后台服务列表 PRD。六个独立字段为服务编号、学员姓名、手机号、服务状态、创建人、创建时间。学员姓名和手机号在 UI 的同一列上下排列，但属于两个独立信息。状态只有待领取、已关闭；具体业务定义未提供。

**预期**：字段表恰有这六个字段行；姓名与手机号分别定义并注明同列组合展示；创建人和创建时间不合并。服务状态有独立小节，保留两个原始枚举并对未知含义 / 流转标待确认，不因未知删除字段。默认排序等未提供事实不编造。

**失败反例**：一行“学员姓名 / 手机号”；一句“服务状态按原型展示”；自动增加处理中。

## O2 多状态与计时规则

**输入**：写后台服务状态章节。固定六个状态：待填写、分配异常、待领取、处理中、已撤回、已关闭。已知：待填写表示学员尚未提交资料；提交后分配失败进入分配异常，成功进入待领取；教师领取后进入处理中；学员可将待领取服务撤回至已撤回；教务可将处理中服务关闭至已关闭；已撤回和已关闭为终态。待领取从分配成功时计时，超过12小时仅显示超时提示，状态仍为待领取。未说明恰好12小时的显示口径、重分配是否重置计时及其他操作。

**预期**：独立状态小节，六个枚举各有业务含义、已知进入和退出条件及角色动作；未知表现、影响和操作逐项待确认。超时写明起点和超过12小时只提示、不流转；边界及重置口径待确认。“超时”不成为第七个状态，不把超过12小时改成自动撤回。

**失败反例**：只罗列六个名称；把已撤回与已关闭合并；编造12小时自动关闭。

## O3 相似弹窗的文案差异

**输入**：后台列表有三个弹窗，都没有输入项、关闭图标，遮罩不可关闭。D1 在待领取点关闭时触发，标题“关闭服务”，正文“该服务尚未领取，确认关闭？”。D2 在处理中点关闭时触发，标题“关闭服务”，正文“该服务正在处理中，关闭后将终止处理，确认关闭？”。二者按钮均为“取消”“确认关闭”，确认进入已关闭并关闭弹窗更新记录，取消不变。D3 点撤回触发，标题“撤回服务”，正文“确认撤回服务{服务编号}？”，按钮“取消”“确认撤回”，确认进入已撤回并关闭弹窗更新记录，取消不变。可操作角色未提供。

**预期**：D1、D2、D3 分别可定位；完整保留三个正文、标题、按钮和变量；可共用布局及确认结构，但必须逐个写差异。明确已提供的关闭约束；角色标待确认，不擅自设为管理员。

**失败反例**：写“三个弹窗均二次确认”；漏 D2 的终止处理文案；把 D3 确认按钮改成“确定”。

## O4 相似角色页面

**输入**：两个服务列表页布局相同。教务看全部记录，教师只看分配给自己的记录；双方都有服务编号、学员姓名、服务状态。教务可关闭待领取或处理中记录，教师只能领取自己的待领取记录；均没有编辑字段入口。教务关闭弹窗正文“关闭后将终止服务，确认关闭？”，按钮“取消”“确认关闭”；教师领取弹窗正文“确认领取该服务？”，按钮“取消”“确认领取”；标题均为“操作确认”。确认分别进入已关闭、处理中并更新记录；取消不变。遮罩及其他关闭方式未明确。

**预期**：两个页面 / 角色都有定位，可复用三字段定义；数据范围、字段可见性、按钮、编辑范围、状态操作、弹窗文案六维度均有明确结论，保留两套弹窗内容和结果；未知关闭方式待确认。

**失败反例**：“教师页同教务页”；教师也可关闭；同一弹窗文案覆盖两角色。

## O5 缺失原型与详略控制

**输入**：写完整 PRD。材料清单为列表页 P1、详情页 P2、关闭弹窗 D1、撤回弹窗 D2。P1 只有字段服务编号、状态；P2 显示服务编号、提交资料，可从 P1 进入并返回。D1 正文可读：“确认关闭服务{服务编号}？”，按钮“取消”“确认关闭”，确认已关闭、取消不变。D2 只知道从 P2 点撤回打开，截图文字不可辨认。状态枚举及角色未知。请背景短写、不要贴原型图、不要写验收章节。

**预期**：P1、P2、D1、D2 全部出现；保留 D1 原文、变量和结果；D2 保留入口并逐项标文案 / 按钮 / 行为待确认，文末汇总；披露材料读取限制，不声称覆盖全部可见交互。状态枚举待确认而不编造。背景短写；不插原型图，不增加验收章节，重要弹窗不能因此省略。

**失败反例**：跳过 P2 或 D2；给 D2 自动生成正式业务文案；重复长篇背景但 D1 只写“确认关闭”。
