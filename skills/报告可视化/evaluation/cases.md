# Evaluation Cases

## A. 触发准确率（Precision）

### 正例

1. “把这份方案做成一个可视化 HTML，风格跟米白深蓝金色的研究报告一样，左侧目录。”
2. “做一个带一级二级菜单的长报告页面，专业、克制、偏纸张质感。”
3. “把现有 React 页面改成左侧导航的研究报告/产品方案展示。”
4. “按 reference HTML 的卡片、表格、Tab 风格重构这个分析页面。”
5. “做一个 AI 产品概念方案页，有角色对比、功能卡片、风险表格。”

期望：触发。

### 反例

1. “做一个暗黑赛博朋克监控大屏。”
2. “只帮我写一个 ECharts 饼图 option。”
3. “设计一个 App Logo。”
4. “生成一张 3D 科技海报。”
5. “公司已经有 Ant Design Pro，严格按现有主题做后台 CRUD 页。”

期望：不触发，或仅在用户明确要求借用布局语言时部分采用。

### 边界例

1. “结构按这个风格，但主色必须是企业绿色。” → 触发；替换色 Token。
2. “左侧菜单 + 大量实时图表。” → 可触发页面骨架；图表工程细节由对应能力处理。
3. “只有 4 个章节，还要二级菜单。” → 触发，但判断是否真的需要二级。
4. “做成 PPT。” → 不触发 Web UI Skill。

## B. 完成准确率

对生成页面逐项评分，每项 0/1：

1. 左侧导航存在且桌面不遮挡正文。
2. 一级/二级菜单层级清楚（若需求有二级）。
3. active 与 hover 状态完整。
4. 使用统一 CSS Variables。
5. 主背景为 warm paper 语义。
6. navy 是结构主色，amber 是小面积强调。
7. Serif 标题 + Sans 正文层级明确。
8. 卡片、表格、Tabs 至少各自符合组件规范，不是随机风格。
9. 900px 左右开始切换移动导航。
10. 360px 无全局横向溢出。
11. 动效克制且支持 reduced motion。
12. 不虚构业务数据。

建议通过线：10/12；其中 1、4、6、9、12 为硬性项。

## C. 输出一致性

同一输入重复生成 3 次，检查：

- 核心 palette 是否一致。
- sidebar 宽度是否保持 248–280px 区间。
- Section Title 是否保持 serif/navy。
- amber 是否仍为辅助强调，而非变成主背景。
- 卡片圆角是否集中在 10–14px。
- hover 位移是否 ≤ 3px。

## D. 人工视觉验收

在 1440×900、900×900、390×844 三个 viewport 截图，对照：

- 第一眼是否像研究/方案报告，而非 SaaS 后台。
- 页面是否有足够留白。
- 左侧栏是否比正文更“安静”。
- 重点是否通过层级与色彩自然出现，而非靠大红大紫。
- 长内容是否容易扫描。
