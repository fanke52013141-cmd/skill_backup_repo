# 公选王PRD撰写专家 5.0：触发与阶段分流回归用例

## 一、正例：应触发本 Skill 并走正确阶段

| 用户输入说法 | 预期识别模式 | 预期首轮动作 |
| :--- | :--- | :--- |
| “这是刚画的打卡活动原型图和几句说明，帮我写 PRD。” | 新建 / 原型转 PRD | **进入 Stage 1**：先审出原型的流程断头路、状态与命名问题，附带 `[产品建议]` 探讨确认，暂不直接刷屏长篇初稿 |
| “按刚才确认的方案，把完整需求文档写出来。” | 新建（Stage 2 放行） | **进入 Stage 2**：按 `prd-template.md` 输出含流程图、全局字典、路由表与分端页面的正式干净 PRD |
| “这份会议纪要直接帮我出完整 PRD 初稿，拿不准的标待确认就行。” | 新建（快捷放行通道） | 尊重明确指令直接进入 Stage 2 出完整稿，仅将核心业务未决点收拢至文末待确认清单 |
| “把这篇老版啰嗦的需求文档按精炼规范重写，方便给后端和 Agent 看。” | 重构改写 | 归一混乱术语，剔除网络报错等废话，重排为“流程图 + 字典路由表 + 分端元素内联交互”结构 |
| “这次 V1.2 只在批改列表加一个‘导出失败重推’按钮和异常状态，帮我更新 PRD。” | 版本增量更新 | 执行涟漪检查，同步更新版本记录、流程图、状态字典与列表页操作，不破坏无关章节 |
| “先别写文档，帮我审一下这套多端原型逻辑有没有漏洞。” | 纯审查 | 仅执行 Stage 1 输出逻辑漏洞与产品修改建议，不重写正文 |
| “这次写 PRD 顺便在最后加一节核心数据埋点。” | 新建 + 点名扩展 | 在标准骨架基础上，按用户明确点名要求追加数据埋点章节（验证“未点名不生成，点名可补充”） |

## 二、反例：不应触发本 Skill

| 用户输入说法 | 不触发原因 |
| :--- | :--- |
| “帮我分析一下公考申论 AI 批改的市场竞品和商业变现模式。” | 属于商业与市场探索，尚未进入产品方案与需求文档阶段 |
| “用 HTML/React 帮我把这个列表页的高保真原型画出来。” | 属于前端/原型绘制任务 |
| “根据这份 PRD 帮我写出 MySQL 建表 DDL 和接口 Swagger 文档。” | 属于纯后端技术架构与数据库设计任务 |
| “帮我把这段年终汇报 PPT 文字润色得更有气势。” | 通用文案润色，与 PRD 无关 |
